# v2 → v3

Replaces the generated `INDEX.md` with `bin/toc`, a table of contents read live from the feature tree. Removes `bin/index` and `bin/adopt`, lets `bin/move` take folders git does not track yet, and gives `bin/check` a new job.

You are on v2 if `VERSION` contains `2`.

**This upgrade needs manual work.** Step 3 adds a notice to a file you own, and step 4 is about your own README.

## 1. Get the patches

```bash
curl -O https://raw.githubusercontent.com/agent-0028/planning-template/main/upgrades/v2-v3/planning.patch
curl -O https://raw.githubusercontent.com/agent-0028/planning-template/main/upgrades/v2-v3/index-deprecation.patch
```

Use the raw files — the `curl` above, or GitHub's **Raw** button. Copy-pasting from GitHub's rendered view of a `.patch` mangles whitespace, and `git apply` will reject the result with an error that does not mention whitespace at all.

## 2. Apply the main patch

```bash
git apply --3way planning.patch
```

Drop `--3way` if it complains. If you have edited anything under `bin/`, use `git apply --reject planning.patch` and resolve the `.rej` files by hand.

The patch touches `bin/`, `test/`, `AGENTS.md`, `INSTRUCTIONS.md`, `VERSION` and `CHANGELOG.md`. It deletes `bin/index` and `bin/adopt` and adds `bin/toc`. It does **not** touch `INDEX.md` or `README.md`.

## 3. Mark `INDEX.md` deprecated — do not delete it

```bash
git apply index-deprecation.patch
```

This inserts one paragraph between the `# Feature index` heading and the `Generated by` line, saying the file is no longer maintained and pointing at `bin/toc`. Nothing else in the file changes.

`INDEX.md` is yours, and v2's `INSTRUCTIONS.md` promised no upgrade would touch it. This is the one exception, which is why it is a separate patch you run on purpose rather than part of step 2. It only adds the notice. Skipping it is fine — the file simply goes stale without saying so.

**If it fails**, you have edited the top of your `INDEX.md`. Paste this in by hand, below the heading:

> **Deprecated.** This file is no longer generated or maintained, and will go stale. Run `bin/toc` for a live listing of every plan. Titles edited by hand here are not carried over: `bin/toc` lists each feature by its folder slug and each document by its first `#` heading. See [How plans are listed](INSTRUCTIONS.md#how-plans-are-listed) in `INSTRUCTIONS.md`. Delete this file whenever you like.

Running it twice is safe: the second run fails rather than inserting the notice again.

**Hand-edited titles are not carried over.** If you corrected titles in `INDEX.md`, those corrections now live nowhere. A document's first `#` heading is its title from here on — fix the heading in the document if one matters.

Delete `INDEX.md` whenever you like, now or later. Nothing reads it.

## 4. Update your README

If your `README.md` mentions `INDEX.md`, `bin/index` or `bin/adopt`, update it. `bin/toc` replaces the index as the place to start; [INSTRUCTIONS.md](../../INSTRUCTIONS.md) covers it under *How plans are listed*.

## 5. Remove anything that ran `bin/index`

A git hook, a CI step, an editor task. `bin/index` no longer exists. `bin/check` still does, and still exits zero on a healthy repo — it now prints warnings instead of comparing an index.

Anywhere you used `bin/adopt`, use git:

```bash
# a folder already under features/<lifecycle>/
git add features/proposed/<slug>

# a folder or file from somewhere else
mv <path> features/proposed/<slug>
git add features/proposed/<slug>
```

## 6. Run the tests, then look

```bash
bin/test
bin/toc
bin/toc --all
```

`bin/test` confirms the patch landed intact. `bin/toc` shows what is in flight; `bin/toc --all` should list every folder under `features/`.

## What changed

- `INDEX.md` is no longer generated. `bin/toc` prints a table of contents read live from the tree, so there is no file to conflict on in a merge.
- `bin/toc` lists features by slug and each top-level document by its first `#` heading, with its path and last-commit date, then names each subfolder one level deep, all sorted alphabetically. It shows `active` and `proposed` by default; `--shipped`, `--abandoned` and `--all` widen it.
- `bin/index` and `bin/adopt` are gone.
- `bin/move` moves a folder whether or not git tracks it yet, and stages all of it. `bin/move` and `bin/delete` no longer touch `INDEX.md`.
- `bin/check` warns about top-level documents with no heading in active and proposed features, and about a missing `CHANGELOG.md`. Warnings never fail it.
- `AGENTS.md` tells agents to orient with `bin/toc` and keeps shipped and abandoned plans out of their default read scope.
